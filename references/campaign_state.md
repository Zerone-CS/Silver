# 长任务状态与恢复

协调者维护本次实验事实，模块返回原件和报告。短任务可沿用已有记录，长任务按 [状态示例](../assets/campaign-state.example.json)保存最小上下文；旧记录中的扩展字段可继续保留。

## 保存什么

- **目标与规则**。负载、有效输出和成功条件、质量/SLO、保护场景、资源与停止预算，引用固定版本的契约。
- **基线与候选**。配置/代码身份、变更差异、run 与比较报告引用、最近决策。分别记录数据有效性、质量/SLO、性能结论、解释及决策，未核验项保留未知。
- **实际部署**。主机、容器、PID 与启动时刻、设备映射、端点、模型和有效配置。记录实际镜像/包/import 路径及构建或源码身份，邻近 checkout 仅在确认被执行时作为来源。
- **接续信息**。活动 run/任务、已登记成本与剩余预算、下一项动作及完成条件、未决问题。使用知识时固定所用快照与来源匹配情况。

例如用 `state/0001.json` 保存状态，`runs/<run_id>/` 保存运行，`analysis/<analysis_id>/` 保存分析。相对路径从 campaign 根目录解析。引用固定路径和 hash，敏感配置用受控存储引用。

run 启动前分配唯一 run_id 和未占用的路径，由采集器创建目录，原件完成后封存。重跑使用新 run_id，修复解析使用新 analysis_id 并记录输入 hash、解析器版本及旧结果。状态在长操作前后、验收和决策后保存新快照；已有原件和判断保留。

## 恢复顺序

1. 读取最新完整状态及当前基线、候选和判定引用，检查文件完整性。
2. 核对真实容器、PID/启动时刻、设备、端点、模型和配置。结合进程及容器归属确认设备占用，显存读数仅作其中一项证据。
3. 检查活动任务的进程与产物。只有开始记录的 run 标为不完整，已完成任务先验收再决定下一动作，防止重复实施或重复扣算成本。
4. 对已生效候选继续验证或恢复，现场变化时记录差异并重新判断已有结果的适用性。缺权限或证据时保存具体恢复条件。

## 决策与收尾

采纳判据沿用 [测量契约](../evaluate/references/measurement_contract.md)。状态分别保存去留决定和核实后的实际部署。回退按 [变更契约](../optimize/references/experiment_contract.md)执行，验收恢复后的身份、端点、worker/模型状态和最小健康请求。

目标满足、预算达到上限、用户停止或合理方向耗尽时收尾。预算到期后只进行已有结果的离线核验及预留范围内的清理。保留约定的最终部署，仅清理本次临时服务和资源。先正常停止待清理服务，超时后核对精确进程身份再升级终止，最终确认相应进程、端口与设备资源释放。保留失败、恢复结果和待处理项。

新建完整优化任务使用 [Round 控制器](round_control.md)管理可执行状态。下文的快照适用于旧记录和额外现场上下文。
