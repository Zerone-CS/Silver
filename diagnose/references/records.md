# 诊断记录

分析以具体 run 的实测吞吐、负载和部署身份为起点，按问题引用必要的请求原件、日志、trace 或对应版本的源码。吞吐计数和窗口沿用 [测量契约](../../evaluate/references/measurement_contract.md)。

记录观测值时给出原件位置、实际字段或事件、单位和采集窗口。注明影响解读的采集工具版本、时钟、设备或 rank 覆盖。派生量写清聚合方式，估计值注明依据，漏采或无法关联的部分保留未知。跨设备重叠的活动分别统计墙钟覆盖和累计耗时。重型 profiling 的诊断运行单独保存，说明可能的扰动，正式收益使用关闭重型 profiler 的可比运行核验。

使用[逐步对账器](step_analysis.md)核对同一 run 和窗口中的输出归属、重复计数及分母，并回查原始请求或引擎事件。手工记录可参考[因子账本示例](../assets/factor-ledger.example.json)。

报告区分实测现象与可能原因。提出原因时，说明它能解释哪段观测、什么结果会削弱或推翻它。需要进一步鉴别时，给出具体动作和判读依据。例如通信事件占时较长时，可用多个 rank 的对齐时间线检查等待是否集中在同一阶段。结论随证据更新，变更的吞吐收益由实际对照核验。
